What is a real-time chat app?

A real-time chat app delivers a message the instant it's sent — over a connection that stays open between your device and the server (a WebSocket) instead of asking “anything new?” every few seconds. That one design choice is why a real-time chat feels like a conversation rather than a mailbox: you watch the typing dots, you see someone come online, and you know the exact moment your message was read. Email, SMS and forum threads are store-and-forward; a real-time chat app is live.

Plus One is built that way from the ground up. Every chat — one-to-one, group chat (GC) or community — rides one live Socket.IO connection, and everything that can be live, is: messages, typing, presence, read receipts, reactions, edits, poll results and even likes on the Network feed.

How Plus One stays real-time

  • Instant delivery: the server pushes each message to every member of the chat the moment it's saved — no refresh, no delay.
  • Typing & presence: typing state broadcasts as you type; online and last-seen update the moment someone connects or leaves.
  • Read receipts done right: one tick when sent, two when delivered to every member, blue when everyone has read — identical logic for 1:1 and groups.
  • Reconnect catch-up: lose signal in a lift and your queued messages send, and pending receipts flush, the second the socket is back.
  • Live polls: vote in a group chat and the bars move on everyone's screen at once.
  • Collaborative notes: shared notes inside a chat use operational transformation, so several people can type together with live cursors.
  • Calls on the same wire: ringing, accept, decline and WebRTC signalling all travel over the same real-time channel.
  • Disappearing ink, in sync: when a timed message expires it vanishes from every device in real time.

For developers: an open-source real-time chat app

Searching for a real-time chat app because you're building one? Plus One's complete source is public under the MIT licence: an Expo / React Native client that runs on iOS, Android and web from one codebase, a Node + Socket.IO + SQLite backend with automatic backups, WebRTC signalling, web and Android push, and a Jupiter-style OT engine for collaborative editing. The repo documents every socket event (message:send, message:read, typing, presence, call:offer…) and ships offline test suites — a working reference, not a to-do demo. Read the code on GitHub →

Real-time chat app questions, answered

What is a real-time chat app?

One that delivers messages the instant they're sent over a persistent connection (WebSockets), with live typing indicators, presence and read receipts — instead of refreshing to check for new messages. Plus One is a free real-time chat app built on Socket.IO.

Is Plus One really real-time?

Yes. A live Socket.IO connection carries messages, typing, presence, read ticks, poll votes and feed reactions as they happen. Go offline and everything catches up automatically when you reconnect.

Can I chat in real time in the browser without installing anything?

Yes — open plusoneco.in/app and start. It installs as a PWA if you want it on your home screen, and the Android and iOS apps share the same account.

Does it work on slow connections?

Yes. The UI is light, chats never autoplay heavy media, messages you send offline are queued, and ticks update once the other side reconnects.

Is it free?

Completely — on web, Android and iOS, with no ads, no in-app purchases and no premium tier. Sign up with a username; no phone number needed.

Is Plus One open source?

Yes, MIT-licensed at github.com/sakshamfit/BROSKIE — Expo/React Native client, Node + Socket.IO backend, WebRTC calls.
